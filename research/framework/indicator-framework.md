# 前置指标与景气传导验证规范

## L1 / L2 / L3 的定义

| 层级 | 含义 | 例子 |
| --- | --- | --- |
| L1 Leading（前置指标） | 可能引发未来经营变化，需验证是否领先及领先多久 | CXO 客户融资、项目启动、订单；VLCC 订单簿、吨海里需求 |
| L2 Coincident（同步指标） | 反映当前市场和经营状态，不等于最上游驱动 | VLCC TCE、商品现货价、产能利用率 |
| L3 Lagging（滞后指标） | 经财务确认或事后兑现 | 已披露收入、毛利率、净利润、FCF |

**层级与研究目标相关**：某指标可以领先财报，但同步于当前供需。TCE 是 VLCC 当前运价的 L2，也是季度利润的先行参考，不能因此等同于船队供给的 L1。

## 每条指标的必要信息

- `id`：全局稳定标识（如 `vlcc.td3c_tce`）。
- `name`、`layer`、`unit`、`frequency`、`definition`：不可缺的口径。
- `mechanism`：**为何**及**经由何环节**影响盈利。
- `lead_horizon`：领先范围是假设还是统计验证，不能捏造精确月数。
- `source`：一手出处或可验证数据供应商，标明是否收费。
- `limitations`：覆盖范围、币种、统计偏差、替代关系等。
- 发生数据更新时另记录 `observation_date`、`retrieved_at`、`source_url`，不把实时值硬塞入静态指标字典。

## 五步因果验证

1. **存在可解释机制**：如融资改善 → 新管线/研发预算增加 → CRO 外包订单。
2. **区分共同原因**：例如汇率、库存、疫情扰动可能同时影响指标与股价。
3. **验证样本稳定性**：观察多个周期，检验正向/反向变化及提前期是否稳定。
4. **建立替代解释**：CXO 融资可能只用于延长现金跑道；VLCC 可用运力可能因港口拥堵临时减少。
5. **定义证伪条件**：连续订单走弱、项目终止、运力集中交付、价格下跌等应影响原假设。

## 更新纪律

优先只跟踪每个赛道 3–5 个核心 L1、2–3 个 L2，季度用 L3 验证。报告要写“数据变化 → 传导 → 结论 → 反证”，不机械堆砌指标，也不把相关性写成必然因果。
